# 第十轮功能修复及验收

## 空数据源原因与恢复

演示启动脚本使用独立的 SQLite 和存储目录，原先处理过的 EduChat 文件没有作为当前用户的数据源登记；旧数据库与输出文件并未被删除。原开发免密用户与页面登录的 admin 也可能不同。启动脚本现统一使用本地 admin，已有数据不自动跨用户迁移。

数据源页可登记本机已有的 `data/preproject/incoming/200/educhat_raw_200.jsonl` 及其 `educhat_manifest.json`。服务端读取清单并校验内容哈希和条数，再登记到当前用户的隔离存储；重复登记复用同一来源。没有这对文件时可选择上传自有文件，或明确使用 TEST-ONLY 数据。实际数据不随审查包分发。来源和许可未经核验时仍禁止正式发布。

## 数据治理和模型验证衔接

独立空数据库的真实 HTTP 验收导入并验证 200 条现有 EduChat，处理完成，得到 200 条合格候选；报告及 JSONL 下载成功。模型验证列出当前用户的候选版本，生成训练配置时校验版本文件哈希、样本 ID 和准入状态，保留来源及许可限制；其他用户不能访问。详见 `evidence/functional_results.json`。前端组件测试使用 API 桩，未进行浏览器操作或视觉验收。

## 清单和模型环境

`scripts/module4/04_make_eval_manifest.py` 是评测清单和 OpenCompass 配置生成器；清单缺失因为默认输出目录从未生成该文件，执行入口先前未检查它。页面可先生成配置；运行前检查清单字段、参数一致性、生成文件的哈希与语法、模型、评测解释器、依赖、CUDA 和题库目录；正式运行还要求相同配置的试运行成功。修改配置后需重新生成或试运行。实际生成和检查过隔离配置，但并未生成评测结果。

检查到 Python 3.10.20、RTX 4060 Laptop GPU 和 NVIDIA 驱动；该解释器缺少 torch、transformers、datasets、peft、llamafactory 及 llamafactory-cli，无法测试 PyTorch CUDA。默认 OpenCompass 环境、所需本地模型和题库尚未就绪。训练和正式评测均未执行；独立环境安装好依赖并提供有权使用的模型与题库后，须重新运行页面前置检查和试运行。题库目录检查只确认存在文件，不能证明所有所选科目齐全。正式运行失败时完整输出保存在服务端本地任务日志中，页面显示简化原因。

## 复现与限制

参阅 `review_package_readme.md`；真实数据需自行提供。独立真实 HTTP 验收脚本为 `python scripts/module4_functional_check.py`，要求存在上述真实输入、已安装后端依赖，且本机 18886 端口可用；它生成隔离测试数据和配置，不执行训练或评测。审查包中的历史第九轮报告是历史记录，不能视为第十轮浏览器或模型运行证明。训练任务管理器为单进程内存状态，服务重启后的训练状态恢复和多实例并发未验收。
